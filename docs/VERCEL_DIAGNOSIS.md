# Deployment status and verification

Verified in production on 2026-11-15 at [nsqk-zeta.vercel.app](https://nsqk-zeta.vercel.app), deployment `88e16a3`. The 300 precomputed periods and Claude both work through public server endpoints. This confirms the deployed code path, not just the local build.

The public frontend and server can render the canonical 1992–2024 dataset from bundled JSON, without contacting Python. All 300 valid full-year periods from 1992–2024 (minimum ten years) are precomputed with the same audited Python algorithm into `analysis/periods/`. `POST /api/analysis` reads the matching artifact, including all 18 monthly hypotheses and, when the period has at least twenty years, all three annual hypotheses. The browser never substitutes statistics from the default period. A Vercel deployment does not need a Python runtime. If a bundle is missing or stale, the API fails explicitly. Local development can still compute a missing period with Python.

Claude uses `ANTHROPIC_API_KEY` inside `app/api/chat/route.ts` only. Configure it under Vercel Project → Settings → Environment Variables for **Production**, as `ANTHROPIC_API_KEY` (no `NEXT_PUBLIC_` prefix). Redeploy after changing the variable. `GET /api/chat` returns only a boolean and model name to check setup, never the key. Then test a real question using the full 1992–2024 period. Anthropic may still reject requests if the account has no credits, lacks model access, or the key is invalid; those are distinct from deployment configuration.

After changing an input series, ENSO source, statistical script, or `docs/APP_TREND_PROTOCOL.md`, rerun `.venv/bin/python scripts/precompute_app_periods.py --jobs 3` and commit the generated bundles together with the code/data change. The generator verifies the source fingerprint of all 300 bundles. The API checks this fingerprint against the canonical full-period bundle, so regenerating it as well is required after a source change.

Verification after redeployment: `GET /api/chat` reports `configured: true`; the default-period map and analysis show data; a full-period Claude question returns a source-bound explanation; several custom periods, including a ten-year interval and one with RX5day annual, return their own period and sample size from `POST /api/analysis`. Test through the public URL without a developer session. A 200 response for the homepage alone does not establish these checks.

Production checks after `88e16a3`: `POST /api/analysis` returned 1992–2001 temperature with 120 months and Holm family 18; 2001–2024 temperature and precipitation with 288 months each and family 18; and 1992–2011 annual Rx5day with 20 years and family 3. Each response included its own selected period and audit provenance. `GET /api/chat` reported `configured: true`; a real Claude reply for temperature in 2001–2024 returned `provider: claude` and an analysis ID containing that period. No credential was sent to the browser or included in these checks.
