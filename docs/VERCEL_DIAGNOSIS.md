# Deployment status and verification

The public frontend can render the canonical 1992–2024 dataset from bundled JSON, without contacting Python. The server now also serves this exact period from its bundled audited result. Other year ranges call `scripts/app_trends.py`, which needs Python, NumPy, SciPy, pandas and statsmodels. A normal Next.js deployment on Vercel does not install those into the Node Function. Therefore custom-period analysis is **not production-ready** there. Do not label an arbitrary selected period as analyzed when its API fails.

Claude uses `ANTHROPIC_API_KEY` inside `app/api/chat/route.ts` only. Configure it under Vercel Project → Settings → Environment Variables for **Production**, as `ANTHROPIC_API_KEY` (no `NEXT_PUBLIC_` prefix). Redeploy after changing the variable. `GET /api/chat` returns only a boolean and model name to check setup, never the key. Then test a real question using the full 1992–2024 period. Anthropic may still reject requests if the account has no credits, lacks model access, or the key is invalid; those are distinct from deployment configuration.

For custom periods, deploy the Python analysis as a separate Python service with `requirements-analysis.txt` and the source files/data it reads, then connect the Next server to that service through an authenticated server-side URL. The Vercel Python runtime supports Python Functions, but co-locating a root `api/` directory with Next `app/api/` routes risks route conflicts and requires integration testing before production. Computing all 21 results at 4,999 bootstrap replicates also needs a verified timeout/caching strategy. Avoid a rushed unverified change to the statistical method or silently reusing full-period results for another period.

Verification after redeployment: `GET /api/chat` reports `configured: true`; the default-period map and analysis show data; a full-period Claude question returns a source-bound explanation; custom-period errors remain clearly labeled until Python service is deployed. Test through the public URL without a developer session. A 200 response for the homepage alone does not establish these checks.
